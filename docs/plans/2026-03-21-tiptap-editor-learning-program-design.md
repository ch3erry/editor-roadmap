# Tiptap 编辑器学习项目设计方案

## 概述
本仓库将承载一个分为五个阶段的学习计划，旨在帮助初学者从零开始：先学习 React 基础，随后深入 Tiptap 编辑器开发，最后攻克受 Notion 启发的“块状编辑（Block-based editing）”核心技术。

本项目采用混合工作区结构：
- **根目录概览文档**：用于展示完整的路线图。
- **五个阶段目录**：每个阶段拥有独立的 `app` 工作区。
- **阶段性概览文档**。
- **每个阶段包含三份需求文档**。

这种结构既保证了阶段边界清晰，又允许后续阶段复用前期的设计思路和代码模式。

## 目标
- 在接触复杂的富文本内部机制前，建立扎实的 React 开发习惯。
- 通过递增的产品需求学习 Tiptap，而非孤立的代码演示（Demo）。
- 引入需求文档和验收标准，使学习过程更贴近真实的团队开发流程。
- 最终完成一个块状编辑器核心项目，掌握 Notion 类编辑器的底层原理。

## 非目标（明确不涉及的内容）
- 1:1 复刻一个完整的 Notion 产品。
- 在第一遍学习中引入高级后端、协同办公、身份认证或数据库系统。
- 在学习者能熟练阅读并修改 React 代码之前，过度优化构建工具。

## 阶段设计
### 第一阶段：React 基础页面
重点关注：渲染、组件、Props、局部状态（State）、事件处理和基础项目结构。在引入编辑器概念前，先建立对常规 UI 开发的信心。

### 第二阶段：React 工程化
加入：路由管理、可复用布局、异步状态、脚本配置、代码检查（Linting）、格式化以及项目组织规范。从“能写页面”向“能维护应用”转变。

### 第三阶段：Tiptap 基础
引入：Tiptap 编辑器实例、入门扩展（Starter Extensions）、编辑器状态同步、工具栏指令以及数据序列化。

### 第四阶段：Tiptap 进阶
引入：自定义扩展、更丰富的编辑器交互、更强的关注点分离，以及面向编辑器的设计决策。

### 第五阶段：块状编辑器核心
构建：类 Notion 风格的块状编辑器核心，包含块数据结构、块操作、斜杠菜单（Slash Menu）行为以及文档持久化。

## 需求模型
每个阶段包含三个需求等级：
- **REQ-01**：引导式配置与初步实现。
- **REQ-02**：受控的功能扩展。
- **REQ-03**：更具独立性的实现与代码重构。

每份需求文档包含以下模块：
- 背景 / 目标 / 非目标
- 功能需求 / 验收标准
- 启动指南 / 建议的文件结构边界
- 常见坑点 / 审查重点

## 协作模式
- 我将在每个阶段开始时提供初始代码。
- 我将解释如何在本地运行应用。
- 我将逐一提供需求文档。
- 学习者负责实现需求。
- 在开启下一个需求前，我会对结果进行代码审查（Review）。

## 关键决策
- 初始搭建不使用独立的 Git Worktree。
- 第一阶段应尽早使用轻量化的现代 React 脚手架，而不是把工具链学习推迟到最后。
- 第五阶段的目标是块状编辑器的底层原理，而非整个 Notion 的产品功能面。
