# Note Workspace 演进路线

## 总体目标
`Note Workspace` 不是一次性练习项目，而是学习计划中的长期产品主线。

它的演进目标是：

> 从一个工程化 `SPA` 壳，逐步演进为具备文档浏览、富文本编辑，再到块编辑能力的知识工作台。

## Stage 1：React 页面与状态基础
### 已完成内容
- 静态页面搭建
- 组件拆分
- `props`
- `state`
- 派生数据
- `localStorage`

### 阶段价值
为后续所有产品页面提供最基础的 React 认知。

## Stage 2：工程化知识工作台
### 目标
建立产品的应用壳与页面系统。

### 关键产出
- `Vite + React + TypeScript`
- `Tailwind CSS`
- 共享布局
- 路由
- Mock 数据
- `Dashboard / Wiki Browser / Document Detail / Settings`

### 阶段意义
这一步不是做编辑器，而是为编辑器提供稳定宿主。

## Stage 3：Tiptap 接入
### 目标
把 `Document Detail` 从只读详情页升级成真正的编辑器承载页。

### 预期演进
- 在详情区接入 `Tiptap`
- 管理编辑器初始化与内容数据
- 建立基础扩展能力
- 让详情页真正变成“文档编辑页”

### 与 Stage 2 的关系
Stage 2 负责壳，Stage 3 负责内容编辑核心。

## Stage 4：编辑体验增强
### 目标
围绕 `Tiptap` 增加更真实的编辑体验能力。

### 可能方向
- 工具栏与格式控制
- Slash Command
- 更丰富的节点类型
- 文档元信息与编辑状态表达

### 原则
仍然围绕同一产品演进，而不是切换产品主题。

## Stage 5：块编辑器与知识结构深化
### 目标
进一步向块编辑器模型与更复杂知识组织靠近。

### 可能方向
- Block-based 交互
- 拖拽与块排序
- 更强的文档树与内容层级映射
- 更接近 Notion 风格的知识组织体验

## 当前演进策略
当前产品演进遵守 3 个原则：

1. 不轻易切换产品主题  
避免每阶段换一个练习项目，导致上下文断裂。

2. 先稳住宿主，再增强能力  
先有应用壳，再有编辑器，再谈复杂交互。

3. 每个阶段只解决一类核心复杂度  
避免在同一阶段同时引入过多新概念。

## 当前结论
产品路线应保持：

```text
React 基础
  -> 工程化 SPA
    -> 富文本编辑器
      -> 编辑体验增强
        -> 块编辑器与知识系统深化
```

这条路线最适合当前学习目标，也能让每一阶段的成果真正积累下来。
