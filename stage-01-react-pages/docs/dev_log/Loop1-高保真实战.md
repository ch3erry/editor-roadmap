# Loop1: 高保真实战

## 本轮目标
这轮不是继续扩功能，而是把 Stage 1 的桌面页面尽量向 `.pen` 稿件对齐，让你看到“高保真还原代码”更像什么。

本轮只服务一个目标：
- 对齐 `stage-01-react-pages/design_docs/task-board-ui.pen` 的桌面画面

不做这些事情：
- 不新增交互
- 不改组件契约
- 不动数据流
- 不优先考虑移动端精修

## 这次是怎么从 `.pen` 读值的
高保真不是靠肉眼猜，而是从设计稿里把关键值量出来。

这次直接从 `.pen` 中提取了这些值：
- 页面宽度：`1200`
- 页面内边距：`40`
- 主区块间距：`24`
- Header 内边距：`28`
- Summary 卡片 padding：`24`
- FilterBar padding：`20`
- TaskSection padding：`24`
- Task item padding：`20`
- 主圆角：`16`
- 主边框色：`#CBCCC9`
- 页面背景：`#F2F3F0`

还对齐了这些字号：
- Header 上标：`13`
- Header 标题：`36`
- Header 描述：`15`
- Summary 标签：`14`
- Summary 数值：`36`
- List 标题：`24`
- Task 标题：`18`
- Task 描述：`14`
- 状态标签：`14`

## 为什么这次很多值要“写死”
因为这轮目标是桌面稿对齐，而不是做一套抽象设计系统。

在真实项目里，如果当前目标是：
- 精确对齐一张已批准桌面稿

那么更合理的做法是先：
- 把关键几何值写死
- 验证画面一致
- 再考虑哪些值值得抽成 token

如果一开始就把所有值抽象成变量或响应式比例，画面通常会先偏掉。

## 这次具体改了什么
### 1. 页面主容器
`.app-container` 从“近似布局”调整成更接近稿件的桌面容器：
- `padding` 改为 `40px`
- `gap` 改为 `24px`
- 保持 `1200` 级别的桌面容器宽度

这让四个主区块之间的垂直节奏与稿件一致。

### 2. Panel 视觉
稿件的 panel 不是重阴影卡片，而是：
- 白底
- 细边框
- `16px` 圆角

所以去掉了之前偏重的“漂浮感”，保留更克制的边框卡片语言。

### 3. Header
Header 主要对齐了：
- `28px` 内边距
- `16px` 左右布局间距
- 标题 `36px`
- 描述 `15px`
- 日期 badge 的 `8x12` padding 和浅灰底色

这里最关键的是：日期 badge 不该做成突出按钮，而是一个低对比的轻标签。

### 4. SummaryCards
Summary 卡片从“能看”调整成更接近稿件：
- 卡片高度拉到接近 `156px`
- padding 改成 `24px`
- 标签 `14px`
- 数值 `36px`
- 说明文字 `13px`
- 内容保持左对齐

这会让 Summary 更像信息卡，而不是仪表盘小组件。

### 5. FilterBar
FilterBar 的关键不是按钮本身，而是“胶囊壳层级”：
- 外层壳：`#E7E8E5`
- 激活项：`#F2F3F0`
- 按钮 padding：`6x12`
- 文案字号：`13/14`

这一步能明显改善“看起来像普通按钮组”与“看起来像设计稿里 pill group”之间的差距。

### 6. TaskList
TaskList 对齐了这些关键值：
- 外层 panel padding：`24px`
- 标题区左右对齐
- 列表项 gap：`16px`
- 单条任务 item padding：`20px`
- 标题 `18px`
- 描述 `14px`
- 状态标签用更贴近稿件的灰绿和浅灰 fill

其中最容易被忽略的是状态标签：
- 已完成不是高饱和绿按钮
- 进行中也不是强调色按钮
- 它们更像轻量状态 pill

## 这轮开发建议
### 建议 1：高保真优先调几何值，不优先调颜色
最先决定画面像不像的，往往不是颜色，而是：
- 宽度
- padding
- gap
- 字号
- 圆角

如果这些不对，再好的颜色也救不回来。

### 建议 2：先看“层级”，再写 CSS
这张稿里最关键的层级是：
- 页面背景
- 白色 panel
- panel 内部浅灰 item
- item 内部文字和 pill

很多人会直接改阴影和边框，但真正影响质感的是层级关系。

### 建议 3：桌面稿精修时，不要过早为移动端让步
这轮你要求的是桌面稿对齐，所以这次应该先把桌面值写准。

如果一开始为了“兼容所有尺寸”过度流式化，通常桌面稿会先偏掉。

### 建议 4：`.pen` 是测量源，不只是截图源
真正高保真时，`.pen` 的价值不只是看图，而是可以直接拿到：
- frame 宽高
- padding
- gap
- 字号
- font family
- fill 色值

这比截图猜测稳定得多。

## 这轮还没有做什么
这轮没有继续做：
- 交互
- `useState`
- 筛选逻辑
- Summary 的动态计算
- 更彻底的设计 token 抽象

因为这些都不是高保真桌面还原的主任务。

## 下一步怎么继续
如果保持当前学习主线，下一步不应该继续抠像素，而应该回到：
- `REQ-01` 的收口 review
- 清理模板残留
- 准备进入下一轮需求

如果以后再做高保真，你可以用这套顺序：
1. 先量主容器
2. 再量主区块 gap
3. 再量 panel padding 和 radius
4. 再量字体
5. 最后才调颜色和状态 pill
