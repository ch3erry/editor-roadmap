# 第一阶段 REQ-01

## 名称
初始化第一个 React 任务板并本地运行

## 背景
本需求是学习者第一次亲手接触真实的 React 项目。目标不是机械地背诵安装命令，而是理解 React 项目是如何创建的、开发服务器如何启动、开发过程中浏览器如何更新，以及高保真设计稿是如何转化为基于组件的页面的。

本需求以经批准的“第一阶段任务板 UX”作为事实来源。

## 设计参考
- Pencil 文件：`stage-01-react-pages/design_docs/task-board-ui.pen`
- 设计说明：`stage-01-react-pages/design_docs/2026-03-21-task-board-ui-design.md`

要求的页面形态为单列任务板，依次包含以下部分：
- `Header` (页眉)
- `SummaryCards` (摘要卡片)
- `FilterBar` (过滤栏)
- `TaskList` (任务列表)

## 目标
在 `stage-01-react-pages/app` 目录下创建一个最小化的 `Vite + React + TypeScript` 项目，在 VSCode 中成功启动，并实现一个严格遵循批准设计的静态任务板页面。

## 非目标 (本阶段不涉及)
- 路由 (Routing)
- 远程数据获取
- 可复用的自定义 Hook
- 状态管理库
- 动态过滤逻辑
- 动态摘要计算
- 添加、删除或编辑任务
- `localStorage` 本地存储
- 除普通浏览器缩放以外的响应式重构工作
- 高级样式系统（如 CSS Modules、Tailwind 或 CSS-in-JS）

## 功能需求
- 学习者必须从零创建项目，而不是从预编写的应用代码开始。
- 应用必须通过标准的 Vite 开发服务器在本地运行。
- 页面必须按正确顺序包含四个批准的区域。
- 页面视觉必须遵循设计的核心结构：
  - 浅色背景
  - 居中的内容列
  - 白色的区域面板
  - 柔和的边框处理
  - 圆角设计
- UI 文案应紧贴设计稿，包括界面中可见的中文标签。
- 实现必须使用 React 组件，而不是将所有内容写在一个庞大的 `App.tsx` 中。
- `TaskList` 必须从存储在独立模块中的静态任务数据进行渲染。
- 必须在专门的类型文件中定义 `Task` 类型。
- 过滤器按钮必须在视觉上呈现，但在本需求中保持静态（无功能）。
- 摘要数值在本需求中可以保持静态，尚不需要进行派生计算。

## 要求的 UI 内容
首次实现应包含以下可见内容或设计稿中的等效内容：

### Header (页眉)
- 眉标文字：`Stage 01 · React Pages`
- 页面标题：`今日任务面板`
- 描述性文案：关于练习组件结构及后续状态管理的说明
- 右侧显示日期徽章

### SummaryCards (摘要卡片)
- `总任务数`
- `已完成`
- `未完成`

第一版可以使用静态数值，如 `4 / 2 / 2`。

### FilterBar (过滤栏)
- 提示文字：解释在 `REQ-01` 中过滤器是静态的
- 三个胶囊状按钮：
  - `全部`
  - `进行中`
  - `已完成`

### TaskList (任务列表)
- 区域标题：`任务列表`
- 元信息文字：表明有四个静态示例任务
- 四个任务卡片
- 每个任务卡片包含：
  - 标题
  - 简短描述
  - 状态徽章

## 验收标准
- 学习者能成功运行文档中的安装和启动命令。
- 浏览器正常显示任务板页面，无构建错误。
- 修改组件文字后，能观察到热更新 (HMR) 效果。
- 页面结构在区域层级上与批准的设计一致。
- 至少以下组件作为独立文件存在：
  - `Header`
  - `SummaryCards`
  - `FilterBar`
  - `TaskList`
- 强烈建议建立独立的 `TaskCard` 组件；如果列表标记过于密集，评审时可能要求强制拆分。
- 任务列表是从导入的静态数组渲染的，而不是复制四个 JSX 代码块。
- 组件文件之外存在 `Task` 类型定义。
- TypeScript 在正常开发启动时未报告阻塞性错误。

## 启动指令
在仓库根目录下运行以下命令：

```bash
cd stage-01-react-pages/app
npm create vite@latest . -- --template react-ts
npm install
npm run dev
```

预期结果：
- Vite 启动本地开发服务器。
- 终端打印出本地 URL。
- 在浏览器中打开该 URL 显示 React 应用。

如果在脚手架开始前 `app` 目录不为空，请先清理占位文件，以便 Vite 初始化程序能干净地写入目录。

## 推荐实施顺序
1. 在 `stage-01-react-pages/app` 中创建 Vite 项目。
2. 在修改任何文件前先启动开发服务器。
3. 检查默认模板，识别 `main.tsx`、`App.tsx` 和基础 CSS 文件。
4. 移除默认的演示内容。
5. 在 `App.tsx` 中构建页面外壳。
6. 将页面内容提取到推荐的组件中。
7. 添加静态任务数据和 `Task` 类型。
8. 完成样式调整，使 UI 与设计稿对齐。

## 建议的文件边界
首次实现应目标建立以下文件：

```text
stage-01-react-pages/app/
  src/
    components/
      Header.tsx
      SummaryCards.tsx
      FilterBar.tsx
      TaskList.tsx
      TaskCard.tsx
    data/
      tasks.ts
    types/
      task.ts
    App.tsx
    main.tsx
    App.css
    index.css
```

指南：
- 保持 `App.tsx` 作为组合层。
- 将静态任务示例放在 `data/tasks.ts` 中。
- 将 `Task` 结构放在 `types/task.ts` 中。
- 将页面级样式放在 `App.css` 中。
- 将重置或基准样式放在 `index.css` 中。

## 交付物
在 `REQ-01` 结束时，仓库应包含：
- 在 `stage-01-react-pages/app` 中一个可运行的 Vite React TypeScript 应用。
- 一个匹配批准布局的静态任务板页面。
- 拆分好的表现层组件。
- 静态任务数据和基础任务类型。

## 常见坑点
- 在确认应用能运行之前就开始修改文件。
- 将所有标记代码都留在 `App.tsx` 中。
- 在 JSX 中直接硬编码四个任务卡片，而不是从数据渲染。
- 将未来的交互逻辑混入静态需求中。
- 在组件结构稳定前过度追求像素级还原。
- 无明确理由地将类型定义放在组件文件内部。

## 评审重点
- 学习者是否理解 `main.tsx` 和 `App.tsx` 的作用。
- 组件边界划分是否合理。
- 静态数据是否与渲染代码分离。
- 页面层级是否匹配设计。
- 学习者能否解释应用如何启动以及热重载如何工作。

## 明确约束
**不要**在本需求中添加可点击的过滤行为或任务完成状态切换。这些行为属于后续需求，提前添加会模糊 `REQ-01` 的学习边界。

## 手把手教学演进顺序

我们按这个顺序推进：

1. 读需求和设计源 ✅
2. 检查本地环境 ✅
3. 创建脚手架 ✅
4. 先把默认项目跑起来 ✅
5. 识别入口文件和渲染链路 ✅
6. 画组件树 ✅
7. 定义 REQ-01 范围内的最小组件职责 ✅
8. 搭页面骨架 ✅
9. 再拆组件 ✅
10. 接静态数据和样式 ✅
11. 做一次自检和 review
